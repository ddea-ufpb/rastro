<objective>
## Goal
Criar o esqueleto executável do Rastro — uv workspace com os quatro módulos (`ingestao`, `nucleo`, `consulta`, `saida`) como pacotes Python independentes, um pacote `app` que compõe o FastAPI, e `web/` com Next.js + TypeScript + shadcn/ui — e um pipeline de CI (GitHub Actions) que fica vermelho quando lint, tipos, fronteiras entre módulos ou testes falham.

## Purpose
Fase 1 (Fundação) é comum à turma: "scaffold com CI que falha quando deve". Sem isso, nenhum módulo prova sozinho os itens do envelope (testes, contrato). A fronteira entre módulos imposta por máquina garante o contrato central do README: núcleo, consulta e saída não sabem como a ingestão lê o CSV.

## Output
- Workspace Python (`pyproject.toml` raiz + `modulos/*/pyproject.toml` + `app/pyproject.toml`, `uv.lock`)
- `app` com `GET /health` respondendo 200
- `web/` Next.js (App Router, TS strict, shadcn/ui) com página inicial placeholder em pt-BR
- `.github/workflows/ci.yml` com jobs `python` e `web`
- Prova registrada no SUMMARY de que cada verificação falha quando deve
</objective>

<acceptance_criteria>

## AC-1: Workspace instala e cada módulo testa sozinho
```gherkin
Given um clone limpo do repositório com uv e Python 3.12
When roda `uv sync --all-packages --locked` e depois `uv run --exact --package rastro-<m> pytest modulos/<m>` para cada um dos 4 módulos
Then a instalação termina sem erro e cada um dos 4 comandos passa, rodando só os testes do próprio módulo
And o ambiente de cada execução contém só o módulo e suas dependências declaradas (sem os outros 3 módulos nem `rastro_app`)
```

## AC-1b: Isolamento quebrado é detectado <!-- audit-added -->
```gherkin
Given um teste em `modulos/consulta/tests/` que importa `rastro_ingestao`
When roda `uv run --exact --package rastro-consulta pytest modulos/consulta`
Then o comando sai com código ≠ 0 (ModuleNotFoundError)
```

## AC-1c: Cobertura mínima por módulo <!-- audit-added -->
```gherkin
Given o pytest de cada módulo configurado com `--cov=rastro_<m> --cov-fail-under=80`
When a cobertura de um módulo fica abaixo de 80%
Then o pytest daquele módulo sai com código ≠ 0
```

## AC-2: App compõe a API
```gherkin
Given o workspace instalado
When roda `uv run pytest app`
Then o teste faz `GET /health` via TestClient e recebe 200 com corpo {"status": "ok"}
```

## AC-3: Fronteiras entre módulos impostas
```gherkin
Given o contrato do import-linter declarando os 4 pacotes `rastro_<m>` como independentes
When algum módulo importa outro (ex.: `rastro_consulta` importa `rastro_ingestao`)
Then `uv run lint-imports` sai com código ≠ 0
And sem esse import o comando sai com 0
```

## AC-4: Web compila com tipos e lint
```gherkin
Given `web/` com Next.js, TypeScript strict e shadcn/ui
When roda `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck` e `pnpm build` em `web/`
Then todos saem com 0 e a página `/` renderiza o texto "Rastro" em pt-BR (`<html lang="pt-BR">`)
```

## AC-5: CI falha quando deve
```gherkin
Given `.github/workflows/ci.yml` rodando em push e pull_request para `main`
When qualquer um destes é quebrado: ruff check, ruff format --check, lint-imports, pytest (qualquer módulo ou app), pnpm lint, pnpm typecheck, pnpm build
Then o job correspondente termina vermelho
And com tudo íntegro os dois jobs terminam verdes
```

## AC-6: Workflow com privilégio mínimo e cadeia de suprimento fixada <!-- audit-added -->
```gherkin
Given `.github/workflows/ci.yml`
When inspecionado
Then declara `permissions: contents: read` no topo e nenhum job pede permissão maior
And toda `uses:` aponta um commit SHA completo (40 hex) com comentário da versão
And cada job tem `timeout-minutes` ≤ 10
And o workflow não usa `pull_request_target` nem segredos
```
